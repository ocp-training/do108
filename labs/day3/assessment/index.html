A Multiple choice

Config You change a ConfigMap that the API reads as environment variables. What happens?

Environment variables are fixed at container start. The new values appear after oc rollout restart. A mounted file can refresh without that restart; an environment variable cannot.

Config A Secret protects a database password because

oc get secret -o jsonpath and base64 --decode print the password. Encoding is not encryption. Anyone who can read the project can read the Secret.

Config Mounting a ConfigMap on a directory

Kubernetes creates one file per key and that directory becomes those files. That is what you want for a web root. It is what you must not do to /etc.

Config On ubi9/httpd-24, the board page is served from

grep '^DocumentRoot' prints /var/www/html. A ConfigMap mounted anywhere else leaves the route unchanged.

Storage The database is a Deployment with no volume. You insert a row, then delete the pod.

The new container starts from the image. The credentials in the Secret are still there. The table lived on the container filesystem, so it is gone.

Storage A new claim stays Pending with “waiting for first consumer”.

The default class on this cluster uses WaitForFirstConsumer. The volume is created when a pod mounts the claim. The claim becomes Bound at that moment.

Storage oc delete pvc on a claim a pod still has mounted

In-use protection holds the claim. It shows Terminating until the last pod releases it. Scaling the database to zero lets that deletion finish, and the reclaim policy Delete then removes the data.

StatefulSet fids-db-0 has a table. You query fids-db-1.

A StatefulSet gives each pod its own claim. It does not replicate PostgreSQL. Two replicas are two databases.

StatefulSet The headless Service in front of fids-db

clusterIP: None is the headless marker. fids-db lists every pod. fids-db-0.fids-db is exactly one pod. The Service must exist before the StatefulSet.

Probes A readiness probe is on /. You delete index.html in one pod.

The process is still running, so this is not a restart. Ready becomes 0/1, the pod leaves the endpoints, and the route keeps returning 200 from the other pods.

Probes A liveness probe points at port 9999, where nothing listens.

Liveness failure kills the container. The restart policy starts it again, the probe fails again, and RESTARTS climbs on every pod. Put liveness back on port 8080.

Resources A pod requests 900Gi of memory. You see

Pending plus FailedScheduling and Insufficient memory is a request problem. The scheduler refused the pod. The container never started, so this is not an OOM kill.

Resources A container hits its memory limit, and another hits its CPU limit.

The memory case is OOMKilled and exit code 137, with empty logs, because the kernel killed the process. A CPU limit throttles. The pod stays Running with zero restarts, only slower.

Autoscaling An HPA shows <unknown> and “no metrics returned”.

Utilization is current use divided by the request. With no CPU request there is nothing to divide by. oc set resources --requests cpu=… is the fix. maxReplicas is the ceiling once metrics exist.
