Guided lab Lab 10.1 — Config maps and secrets
Goal. Put the board content in a config map and the database credentials in a secret, and see what survives a restart. Time. 25 minutes. Prerequisites. The ${U}-platform project from day 2.

  1. Write the page, then make a config map of it:

    [you@laptop ~]$ oc project ${U}-platform [you@laptop ~]$ mkdir -p ~/do108/day3 && cd ~/do108/day3 [you@laptop ~]$ cat > index.html <<'PAGE' <!doctype html> <html><head><title>NCE - Departures</title></head> <body><h1>Nice Cote d'Azur - Departures - Terminal 2</h1> <p>AF7701 08:15 Paris CDG - Boarding</p> <p>BA2633 09:40 London LGW - On time</p> </body></html> PAGE [you@laptop ~]$ oc create configmap fids-page --from-file=index.html=./index.html [you@laptop ~]$ oc get configmap fids-page -o yaml | head -20

  2. Mount it over the web root:

    [you@laptop ~]$ oc set volume deployment/fids-web --add \ --type configmap --configmap-name fids-page \ --mount-path /var/www/html --name page [you@laptop ~]$ oc rollout status deployment/fids-web [you@laptop ~]$ FIDS=$(oc get route fids-web -o jsonpath='{.spec.host}') [you@laptop ~]$ curl -s http://$FIDS/ | head -3

    The real departures page. Note that setting the volume triggered a rollout — the pod template changed, so new pods were created.

  3. Now prove that it survives. This is the whole point of the chapter:

    [you@laptop ~]$ oc delete pod -l app=fids-web [you@laptop ~]$ sleep 20 && curl -s http://$FIDS/ | head -3

    Still there. On day 2 the same test lost the page, because the content lived in the container. Now it lives in the cluster, and the container is disposable again.

  4. Change the content without touching the application:

    [you@laptop ~]$ sed -i 's/Boarding/Final call/' ~/do108/day3/index.html [you@laptop ~]$ oc set data configmap/fids-page --from-file=index.html=~/do108/day3/index.html [you@laptop ~]$ sleep 60 && curl -s http://$FIDS/ | grep -i call
    i
    Note

    Mounted files are refreshed by the kubelet, but not instantly — allow up to about a minute. If you cannot wait, or if the application caches its configuration, oc rollout restart deployment/fids-web is the reliable answer.

  5. Create the database credentials as a secret — never again on a command line:

    [you@laptop ~]$ oc create secret generic fids-db-credentials \ --from-literal=POSTGRESQL_USER=fids \ --from-literal=POSTGRESQL_PASSWORD=fids-training \ --from-literal=POSTGRESQL_DATABASE=flights [you@laptop ~]$ oc get secret fids-db-credentials NAME TYPE DATA AGE fids-db-credentials Opaque 3 5s

  6. See how little a secret protects, so that you never over-trust one:

    [you@laptop ~]$ oc get secret fids-db-credentials -o jsonpath='{.data.POSTGRESQL_PASSWORD}' | base64 --decode; echo fids-training

    One command, no privilege beyond reading the project. Encoding is not encryption.

  7. Deploy the database using the secret:

    [you@laptop ~]$ oc create deployment fids-db --image=quay.io/sclorg/postgresql-15-c9s:latest [you@laptop ~]$ oc set env deployment/fids-db --from secret/fids-db-credentials [you@laptop ~]$ oc rollout status deployment/fids-db [you@laptop ~]$ oc set env deployment/fids-db --list

    The values are referenced, not copied: the deployment holds a pointer to the secret. Rotating the password means changing the secret and restarting, not editing the deployment.

  8. Prove the database works, then destroy it and see what you lose:

    [you@laptop ~]$ oc exec deployment/fids-db -- psql -U fids -d flights \ -c "CREATE TABLE flight (id int, dest text); INSERT INTO flight VALUES (7701,'CDG');" [you@laptop ~]$ oc exec deployment/fids-db -- psql -U fids -d flights -c "SELECT * FROM flight;" [you@laptop ~]$ oc delete pod -l app=fids-db [you@laptop ~]$ sleep 30 && oc exec deployment/fids-db -- psql -U fids -d flights -c "SELECT * FROM flight;" ERROR: relation "flight" does not exist

    The credentials survived. The data did not. That is the second half of this chapter.

?
Check

The board shows real departures and keeps showing them after every pod in the deployment is deleted; the database starts from a secret and holds no password on any command line; and you have watched a table disappear because nothing persisted it.
